# گزارش تحویل فنی ادغام پرینتر

## هدف

بخش جدید پرینتر باید روی همان Arduino UNO ادغام شود که اکنون محورهای X و Y دستگاه را کنترل می‌کند. پیاده‌سازی جدید نباید پایه‌ها، پروتکل سریال یا رفتار فعلی حرکت را مختل کند.

مخزن مرجع:

- Repository: `https://github.com/emreboyozak-coder/XYPrinter`
- Branch: `main`

## برد کنترل

- Arduino UNO
- میکروکنترلر ATmega328P با کلاک 16 MHz
- مبدل USB-to-Serial از نوع CH340
- پورت فعلی در Windows معمولاً `COM6`
- منطق دیجیتال 5V
- Flash حدود 32 KB و RAM برابر 2 KB

به‌دلیل RAM محدود، از بافرهای بزرگ و استفاده گسترده از کلاس `String` در Firmware اجتناب شود.

## پایه‌های رزروشده

| پایه | وظیفه |
|---|---|
| D2 | جهت محور X، متصل به DIR درایور X |
| D3 | پالس محور X، متصل به PUL درایور X |
| D6 | جهت محور Y، متصل به DIR درایور Y |
| D7 | پالس محور Y، متصل به PUL درایور Y |
| D8 | Enable مشترک درایورهای موتور |
| D0/RX | ارتباط سریال USB |
| D1/TX | ارتباط سریال USB |
| GND | مرجع مشترک بخش کنترل |

این پایه‌ها نباید برای بخش پرینتر استفاده مجدد شوند.

پایه‌های فعلاً آزاد عبارت‌اند از `D4`, `D5`, `D9` تا `D13` و `A0` تا `A5`. توجه شود که D13 به LED داخلی، D10 تا D13 به SPI و A4/A5 به I2C وابسته‌اند.

## اتصال فعلی موتورها

محور X:

- Arduino D3 به PUL+ درایور X
- Arduino D2 به DIR+ درایور X
- Arduino GND به PUL-/DIR- درایور X

محور Y:

- Arduino D7 به PUL+ درایور Y
- Arduino D6 به DIR+ درایور Y
- Arduino GND به PUL-/DIR- درایور Y

پایه D8 برای Enable استفاده می‌شود و Firmware فعلی سطح LOW را حالت فعال در نظر می‌گیرد.

## کالیبراسیون حرکت

- 400 پالس برابر یک دور موتور
- یک دور برابر 4 mm حرکت خطی
- 100 پالس برابر 1 mm
- هر پالس برابر 0.01 mm

محدوده Feed:

- حداقل 1 step/s
- حداکثر 2000 step/s
- مقدار پیش‌فرض 20 step/s
- سرعت خطی بر حسب mm/s برابر `F / 100` است

محدوده شتاب:

- حداقل 100 step/s²
- حداکثر 5000 step/s²
- مقدار پیش‌فرض 800 step/s²
- سرعت شروع و پایان Ramp برابر 20 step/s

## ارتباط سریال

- Baud rate: 115200
- Data bits: 8
- Parity: None
- Stop bits: 1
- Flow control: None
- Encoding: ASCII
- پایان هر پیام: newline یا `\n`
- حداکثر طول خط فعلی: 128 کاراکتر

Arduino پس از روشن‌شدن یا Reset پیام `READY` می‌فرستد. بازکردن پورت USB معمولاً Arduino را Reset می‌کند و موقعیت داخلی X/Y دوباره صفر می‌شود.

## قرارداد فرمان‌ها

تمام فرمان‌ها با `$` شروع می‌شوند، شناسه ID دارند و با newline تمام می‌شوند.

نمونه PING:

```text
$ID=42 CMD=PING
```

نمونه حرکت:

```text
$ID=43 CMD=MOVE X=100.000 Y=25.000 F=1500.0 A=400.0
```

پارامترها:

- X و Y: مختصات مطلق بر حسب mm
- F: سرعت بر حسب step/s
- A: شتاب بر حسب step/s²

Arduino ابتدا فرمان دریافتی را Echo می‌کند:

```text
RX:$ID=43 CMD=MOVE X=100.000 Y=25.000 F=1500.0 A=400.0
```

پاسخ موفق:

```text
@OK ID=43 CMD=MOVE
@DONE ID=43 CMD=MOVE
```

پاسخ خطا:

```text
@ERROR ID=43 CODE=INVALID_COMMAND
```

برنامه کامپیوتر پیام‌های `READY` و `RX:` را نادیده می‌گیرد، `@ERROR` و `@ALARM` را خطا می‌داند و برای تکمیل عملیات منتظر `@DONE` می‌ماند.

## فرمان‌های واقعاً پیاده‌سازی‌شده

Firmware فعلی فقط فرمان‌های زیر را اجرا می‌کند:

- `PING`
- `STATUS`
- `MOVE`

در Python متدهایی برای `TRIGGER`, `STOP`, `ESTOP`, `HOME` و `JOG` وجود دارند، اما Firmware فعلی آن‌ها را پیاده‌سازی نکرده و برای آن‌ها `UNSUPPORTED_COMMAND` برمی‌گرداند.

## پیشنهاد قرارداد پرینتر

فرمان پیشنهادی شروع چاپ:

```text
$ID=200 CMD=PRINT MS=50
```

پاسخ پیشنهادی:

```text
@OK ID=200 CMD=PRINT
@DONE ID=200 CMD=PRINT
```

فرمان‌های احتمالی دیگر:

- `PRINT_STATUS`
- `PRINT_RESET`
- `PRINT_STOP`

نام و پارامترهای نهایی باید پس از مشخص‌شدن رابط الکتریکی پرینتر تعیین شوند.

## اطلاعاتی که قبل از اتصال پرینتر باید مشخص شوند

- ولتاژ ورودی Trigger
- فعال‌شدن با لبه مثبت یا منفی
- حداقل عرض پالس Trigger
- وجود ورودی Enable
- وجود خروجی Ready
- وجود خروجی Busy
- وجود خروجی Fault یا Alarm
- سطح ولتاژ سیگنال‌ها: 5V، 12V یا 24V
- Open Collector بودن یا نبودن خروجی‌ها
- نیاز به ایزولاسیون اپتوکوپلر
- چاپ در حالت توقف یا هنگام حرکت

Arduino نباید بار صنعتی، شیر برقی، سلونوئید، رله پرقدرت یا سیگنال 12/24V را مستقیم راه‌اندازی کند. بسته به سخت‌افزار باید از اپتوکوپلر، MOSFET، ترانزیستور درایور، دیود Flyback، رله یا مبدل سطح مناسب استفاده شود.

## محدودیت مهم Firmware فعلی

تولید پالس موتور blocking است:

1. حرکت کامل X اجرا می‌شود.
2. حرکت کامل Y اجرا می‌شود.
3. پاسخ پایان فرمان ارسال می‌شود.
4. Arduino دوباره سریال را بررسی می‌کند.

نتایج:

- X و Y هم‌زمان حرکت نمی‌کنند.
- هنگام حرکت فرمان سریال جدید پردازش نمی‌شود.
- STOP یا ESTOP نرم‌افزاری در وسط حرکت فوری نیست.
- فرمان چاپ در وسط حرکت دریافت نمی‌شود.

اگر چاپ فقط پس از توقف انجام می‌شود، ترتیب مناسب این است:

```text
MOVE -> DONE -> PRINT -> DONE -> MOVE
```

اگر چاپ باید هنگام حرکت انجام شود، تولید پالس باید به Timer/Interrupt و یک state machine غیرمسدودکننده منتقل شود تا Serial، توقف اضطراری و Trigger چاپ هم‌زمان مدیریت شوند.

## مختصات

موقعیت Arduino از نوع open-loop است و Encoder وجود ندارد. موقعیت از تعداد پالس‌های ارسال‌شده تخمین زده می‌شود و Step ازدست‌رفته قابل تشخیص نیست.

در بخش Pick and Place تبدیل مختصات در برنامه کامپیوتر انجام می‌شود:

```text
Machine X = taught origin X + CSV X
Machine Y = taught origin Y - CSV Y
```

جهت Y فایل CAD نسبت به ماشین معکوس است. این معکوس‌سازی در Python انجام می‌شود، نه در Firmware.

## اصول الزامی سازگاری

- پایه‌های D2، D3، D6، D7، D8، D0 و D1 تغییر نکنند.
- Baud rate برابر 115200 باقی بماند.
- قالب `$ID=<n> CMD=<command>` حفظ شود.
- پاسخ هر فرمان همان ID را برگرداند.
- موفقیت با `@OK` و تکمیل با `@DONE` اعلام شود.
- خطا با `@ERROR` یا `@ALARM` اعلام شود.
- پیام‌ها ASCII و line-oriented باقی بمانند.
- رفتار `PING`, `STATUS` و `MOVE` شکسته نشود.
- واحدهای X/Y، F و A تغییر نکنند.
- فرمان چاپ timeout و گزارش خطای مشخص داشته باشد.
- `@DONE CMD=PRINT` فقط پس از تکمیل واقعی چاپ ارسال شود.

## دستور کوتاه برای Codex دوم

بخش پرینتر را روی همان Arduino UNO ادغام کن. پایه‌های D2/D3 برای X، D6/D7 برای Y، D8 برای Enable و D0/D1 برای USB Serial رزرو هستند. ارتباط 115200 و مبتنی بر خطوط ASCII با قالب `$ID=<n> CMD=<command>` است. Firmware فعلی فقط PING، STATUS و MOVE را پشتیبانی می‌کند. اگر چاپ در حالت توقف انجام می‌شود، ترتیب `MOVE -> DONE -> PRINT -> DONE` را حفظ کن. اگر چاپ حین حرکت لازم است، کنترل پالس را به Timer/Interrupt و state machine غیرمسدودکننده تبدیل کن. ابتدا مشخصات Trigger/Ready/Busy/Fault و سطح ولتاژها را تعیین کن. هیچ ورودی صنعتی یا بار 12/24 ولتی را مستقیم به Arduino متصل نکن. نتیجه سیم‌کشی، پایه‌ها، پروتکل، تست سخت‌افزار و commit را گزارش کن.
